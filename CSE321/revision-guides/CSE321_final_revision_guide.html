📖 Theory ▼
Module 5 — File Systems (Topics 20–23)
File Concept, Attributes, Operations LOW

Disk hardware: platter/spindle/surface/read-write head/track/sector. Moving the head toward an inner track = forward; toward an outer track = backward — a slide-specific directional fact.

File attributes: name, identifier (inode #), type, location, size, protection, timestamps/user ID. Operations (Silberschatz, 8): create, open, write, read, seek, delete, truncate, close.

Common error: the slide deck's own list only names 6 ops (create/read/write/delete/truncate/reposition, no open/close) — know the fuller 8-op list as primary, but don't be thrown by the 6-op phrasing.
File System Structure, Inode, Directory MED

5-layer stack: Application → Logical FS (metadata/inode/directory/protection) → File-Organization Module (logical→physical block map, free space) → Basic FS (generic device commands) → I/O Control (drivers) → Devices.

NTR's own framing (Ext2/VSFS block-group layout): Boot Sector | Block Group 0 | Block Group 1 | ..., each group = Superblock | Group Descriptor | Block Bitmap | Inode Bitmap | Inode Table | Data Blocks.

Directory = list of (name, inode#) pairs + built-in ./.. entries. Root inode number = 2 in most UNIX file systems — a quotable fact.

Why it matters: open() is expensive (directory scan → inode lookup → open-file table entry); read()/write() afterward are cheap because the lookup is cached.
Indexed Allocation & the UNIX Inode HIGH

Inode = metadata + block pointers: 12 direct, 1 single-indirect, 1 double-indirect, 1 triple-indirect (classic layout — a problem may give different counts, always use the stated numbers).

Two distinct skills: (1) max file size — sum addressable bytes across all pointer levels; (2) inode disk address — locate inode N's byte/sector position via offset = inode# × inode_size.

Disk accesses to read a block (inode assumed cached): direct=1, single=2, double=3, triple=4 — add 1 at every level if the inode itself isn't cached.

Crash Consistency & Journaling HIGH

A logical FS operation = multiple physical writes (bitmap, inode, data block) — not atomic, so a crash mid-operation can leave the FS inconsistent. fsck (old fix) scans the whole disk at reboot — slow, only guarantees structural sanity.

Journaling: write a transaction (TxB + blocks + TxE) to a log first; only checkpoint to final location once TxE is safely on disk. Crash before TxE → discard; crash after TxE → redo by replaying the log.

Full protocol: Journal write → Journal commit (TxE) → Checkpoint → Free. Revoke records prevent replaying a stale write to a block that's since been reused by a different file.

Module 6 — Memory Management (Topics 24–28)
Address Binding, Logical vs Physical, MMU MED

Three binding times: compile-time (absolute code), load-time (relocatable), execution-time (needs hardware support — most modern systems). Only execution-time binding makes logical ≠ physical address.

Relocation register: Physical = Logical + Relocation. Base/limit registers enforce protection: base ≤ address < base+limit, else trap.

Dynamic loading (routine loaded only when called) vs dynamic linking (library linked at runtime, one shared copy for all processes) vs static linking (baked in at compile time).

Contiguous Allocation & Fragmentation LOW

Not in the theory slide deck at all — textbook-only, still in the confirmed Topic 20–32 range. Dormant in every recent Final sitting (0/4) but nominally in-scope.

First-fit (fast) / best-fit (least waste, many tiny holes) / worst-fit (performs worst overall). External fragmentation → fixed by compaction (needs dynamic relocation). Internal fragmentation → allocated block larger than needed.

50-percent rule: ~1/3 of memory can become unusable to external fragmentation under random alloc/dealloc patterns — the classic motivation for paging.

Paging: Page Table, Frames, Address Translation, TLB HIGH

Physical memory → fixed-size frames; logical memory → same-size pages. Page table maps page# → frame#. Eliminates external fragmentation entirely (frames need not be contiguous).

Translation: page# = LA ÷ page_size, offset = LA mod page_size, PA = frame# × page_size + offset. Same math whether addresses are given in decimal (divide/mod) or as binary strings (cut the bits directly).

TLB caches recent page-table entries to avoid two memory accesses per reference. Multilevel paging pages the page table itself when it's too large for one frame — the densest calculation skill in this module.

Virtual Memory & Demand Paging HIGH

Pages loaded only when referenced (lazy). Valid-invalid bit now means: valid = in memory, invalid = either illegal or legal-but-not-loaded-yet.

Page fault sequence: trap → check legality → find/evict a frame → schedule disk read → update page table → restart the instruction from scratch (not resume mid-instruction).

EAT with page faults: dominated by disk I/O (ms range, ~10⁵–10⁶× slower than memory) — even a tiny fault probability causes severe slowdown.

Page Replacement: FIFO, Optimal, LRU HIGH

FIFO: evict oldest-loaded — simple, suffers Belady's Anomaly (more frames can mean more faults). Optimal: evict page used furthest in future — best possible, unimplementable (needs future knowledge). LRU: evict least-recently-used — practical approximation, no Belady's Anomaly.

Common error: the current era's exams like to give a deliberately "buggy"/modified replacement rule (e.g. "also replace the next-frame page") — read the question's exact rule, don't assume textbook-standard FIFO/LRU/OPT mechanics.
Module 7 — Protection (Topics 29–30) — conceptual only, no math
Protection Goals, Domain of Protection, Access Matrix MED

Protection vs Security: Protection = internal, controls access of already-authenticated entities per policy. Security = defends against external threats. Mechanism (what the OS builds) vs Policy (who's allowed what).

Domain = set of (object, rights) pairs. UNIX domain = user-id, switched via setuid, su, sudo. Android = per-app UID/GID + isolated UIDs.

Access matrix: rows = domains, columns = objects, entry = allowed operations. Four special rights: copy (*, re-copyable if starred), owner, control (domain-on-domain), switch/transfer. Implementations: global table, ACL (per-object), capability list (per-domain), lock-key.

Revocation, MAC vs DAC, Capability-Based Systems LOW

Revocation dimensions: immediate/delayed, selective/general, partial/total, temporary/permanent. ACL revocation = easy (edit one list). Capability revocation = hard (rights decentralized) — fixed via reacquisition, back-pointers, indirection, or keys.

DAC: owner decides, can change (standard UNIX/Windows permissions). MAC: system enforces fixed labels, owner cannot override (SELinux, TrustedBSD, Trusted Solaris). POSIX capabilities: permitted/effective/inheritable bitmaps, once revoked cannot be reacquired.

Exam note: not appeared as exam content in any sampled sitting — keep for completeness, but this is the lowest-yield theory in Module 7.
Module 8 — Security (Topics 31–32) — conceptual only, no math
Security Problem, Violations, Program Threats MED

CIA + Authenticity goals. Violation categories (what): confidentiality, integrity, availability, theft of service, DoS. Violation methods (how): masquerading, replay, MITM, session hijacking, privilege escalation — don't conflate the two lists.

4 official security levels: Physical, Application, OS, Network (human/social-engineering is a cross-cutting risk, not a formal 5th level).

Program threats: Trojan Horse, Trap Door, Logic Bomb, Buffer Overflow (bounds-check failure, trampoline redirection). Malware terms: spyware, ransomware, RAT, code-injection. Virus (needs host + human action, 10 types incl. Armored) vs Worm (standalone, self-propagating — Morris Worm specifics: finger/sendmail bugs, rsh trust, 99-line grappling hook, reinfects every 7th time).

Security Defenses: Crypto, Firewalls, IDS/IPS LOW

Defense in depth: security policy (target state) vs vulnerability assessment (actual state vs policy). Cryptography is textbook-only, not in the slide deck and has never appeared on any sampled sitting — symmetric (DES/AES, fast, key-distribution problem) vs asymmetric (RSA, slow, solves distribution, used for key exchange/signatures).

Firewalls: network/packet-filtering, application-level (proxy), personal, system-call. Weaknesses: tunneling (smuggle disallowed protocol inside an allowed one), spoofing (forge trusted IP/hostname).

IDS (alerts only) vs IPS (blocks). Signature-based (precise, blind to zero-days) vs anomaly-based (catches zero-days, noisier).

❓ Short Questions ▼

Tap a question to reveal the answer. Try to recall first.

Why is open() expensive but read()/write() cheap afterward?HIGH
open() must scan the directory structure, find the inode, and populate the system-wide + per-process open-file tables — a one-time cost. read()/write() reuse that cached FCB, so they only touch data blocks, not the lookup path.
What's the root directory's inode number in most UNIX file systems?MED
2 — not 0 or 1. A specific, quotable fact worth memorizing directly.
How many disk I/Os does a single write() that appends a new block cost?HIGH
5: read data bitmap → write data bitmap → read inode → write inode → write the data block itself. Creating the file first (before any write) adds further I/O for the new directory entry.
Why does journaling only need to scan the log on recovery, not the whole disk like fsck?HIGH
The journal already records exactly which transactions were in progress and whether they completed (via TxB/TxE), so recovery only needs to replay or discard those small entries — it doesn't need to cross-check the entire disk's bitmaps and inodes like fsck does.
What problem do revoke records solve in journaling?MED
Prevents a crash-recovery replay from overwriting a reused block's new data with a stale logged write to that same block number (e.g. a deleted directory's block reused by a new file) — recovery skips replaying any write to a block later revoked.
Why does execution-time binding require hardware support?MED
Because the logical and physical addresses differ and can change while the process runs (e.g. if it's relocated in memory) — a base/relocation register must translate every reference at run time; without that hardware, only compile-time/load-time binding (fixed addresses) would be possible.
Why does paging eliminate external fragmentation?HIGH
Because a process's pages can be placed in any free frames anywhere in physical memory — they don't need to be contiguous, so there's no "hole too small to use" problem the way there is with contiguous allocation.
Why is a TLB miss more expensive than a hit — precisely how many memory accesses does each cost?HIGH
Hit: 1 memory access (the TLB itself isn't memory). Miss: 2 memory accesses — one to read the page table entry, one to fetch the actual data — plus the TLB lookup time either way.
Why is a page fault's trapping instruction restarted from scratch rather than resumed?MED
The hardware generally can't preserve enough mid-instruction state to resume exactly where it left off, so the safe approach is to restart the whole instruction once the needed page is loaded.
Why is Optimal page replacement not implementable in practice?MED
It requires knowing the future reference string in advance (which page will be used furthest away) — real systems can't know this, so Optimal is used only as a theoretical benchmark to measure how close FIFO/LRU get.
What's the difference between the access matrix's `owner` and `control` rights?MED
`owner` lets a domain add/remove rights in any domain's entry for a specific object. `control` lets a domain modify the rights of a different domain itself (a domain acting as an object) — owner governs object rights, control governs domain rights.
Why is revocation easy under access lists but hard under capability lists?LOW
ACLs centralize rights at the object (one list to edit). Capabilities are copies distributed across domains — there's no single place to revoke from, which is why indirection/keys/back-pointers exist, to recover a central point of control.
What's the key difference between a virus and a worm?HIGH
A virus needs a host program and human action to spread (running/opening an infected file). A worm is standalone, self-replicating via a spawn mechanism, and needs no human action — it propagates autonomously across a network.
What's the difference between IDS and IPS?MED
IDS only monitors and alerts on suspected intrusions. IPS can actively block or prevent the detected threat, not just flag it.
Why is asymmetric encryption usually paired with symmetric encryption in practice?LOW
Asymmetric encryption is slow but solves the key-distribution problem, so it's used just to exchange a symmetric session key; the bulk of the actual communication then uses fast symmetric encryption — a hybrid approach.
🧮 Analytical Questions ▼
Q1TLB access = 20 ns, memory access = 100 ns, hit ratio = 80%. Find the Effective Access Time.HIGH▼
1
Hit case: TLB access + 1 memory access = 20 + 100 = 120 ns.
2
Miss case: TLB access + 2 memory accesses (page table, then data) = 20 + 100 + 100 = 220 ns.
3
EAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = 140 ns.
Key insight: memorize the formula's structure (hit = 1 memory access, miss = 2), not the numbers — this generalizes to any given hit ratio/times.
Exam note: appeared in every single sampled sitting, both eras — the single most reliable fixture on the whole exam.
Q2EAT = 116 ns, TLB access = 10 ns, memory access = 100 ns. Find the hit ratio.HIGH▼
1
Let hit ratio = h. Hit case = 10+100 = 110. Miss case = 10+100+100 = 210.
2
EAT = h(110) + (1−h)(210) = 210 − 100h.
3
116 = 210 − 100h → 100h = 94 → h = 0.94 (94%).
Key insight: the current-era exam explicitly tests solving for any one of hit ratio / TLB time / memory time given EAT and the rest — set up the same two-branch equation and solve algebraically instead of memorizing only the forward direction.
Q3Inode #32, inode size 256 B, block size 4 KB, inode table starts at 12 KB, disk sector size 512 B. Find the byte address and the sector address.HIGH▼
1
Byte offset = 32 × 256 = 8,192 B = 8 KB. Byte address = 12 KB + 8 KB = 20 KB.
2
Block# = (32 × 256) / 4096 = 8192/4096 = 2.
3
Sector address = (2 × 4096 + 12288) / 512 = 20480 / 512 = sector 40.
Exam note: near-universal in File Systems sections — always phrased with a specific inode size, block size, sector size, and a list of reserved leading blocks (superblock, journal, bitmaps). Read which blocks are reserved before the inode table carefully.
Q4Inode has 8 direct, 2 single indirect, 2 double indirect, 2 triple indirect pointers. Block size = 32 B, pointer size = 4 B. Find the max file size.HIGH▼
1
Pointers per block = 32/4 = 8.
2
Direct: 8×32 = 256 B. Single indirect: 2×8×32 = 512 B.
3
Double indirect: 2×8²×32 = 4,096 B. Triple indirect: 2×8³×32 = 32,768 B.
4
Sum = 256+512+4096+32768 = 37,632 bytes.
Common error: this inode has 2 of each indirect type, not the usual classic 12-1-1-1 — always use the problem's stated pointer counts. The inverse variant (given max size, solve for an unknown pointer count) is also common — same formula, solve algebraically for the unknown term.
Q58-bit logical address space, page size = 16 B, page-table entry size = 4 B, main memory = 512 B. Derive the paging levels needed and translate a given address.HIGH▼
1
Offset bits n = log2(16) = 4.
2
Page-number bits P = 8 − 4 = 4.
3
Bits per level k = log2(16/4) = log2(4) = 2.
4
Levels = ceil(4/2) = 2 → two-level paging. Split: p1 (2 bits) | p2 (2 bits) | offset (4 bits) = 8 bits total. Check: each table = 2²×4B = 16B = exactly 1 frame ✓.
5
To translate: convert address to binary, cut into p1|p2|d, look up p1 in the outer table for the inner table's frame, look up p2 in that inner table for the final frame, append d unchanged.
Exam note: if step 4 gives 3+ levels, keep chunking the same way — the outermost level absorbs whatever bits are left, even less than a full k. This is the module's densest and most heavily tested individual skill.
Q6Reference string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1, 3 frames. Trace FIFO, LRU, and Optimal; report fault ratio and hit ratio.HIGH▼
1
FIFO: evict the oldest-loaded resident page on each fault → 15 faults total (of 20 references).
2
LRU: evict the page unused longest looking backward → 12 faults.
3
Optimal: at each fault, evict whichever resident page is used furthest away (or never again) looking forward → 9 faults.
4
Fault ratio = faults/total refs × 100%; hit ratio = 100% − fault ratio. E.g. FIFO: 15/20 = 75% fault, 25% hit.
Common error: the current era likes a deliberately modified rule (e.g. "also evict the next-frame page" instead of standard FIFO) — trace exactly what the question defines, not the textbook algorithm from memory. Also check whether the answer wants raw fault counts or a percentage — the practice-sheet format asks for percentages.
Q7A crash occurs mid-write to a file. Given which of 2–3 writes (bitmap/inode/data) succeeded, deduce the resulting inconsistency and its visible symptom.MED▼
1
List the writes a single append normally needs: (a) mark bitmap used, (b) update inode pointers/size, (c) write data block.
2
For the given crash point, identify which of (a)/(b)/(c) completed and which didn't.
3
Reason the symptom: e.g. bitmap marked used but inode never updated → a block is "lost" (unreferenced but unusable, disk space shrinks over time); inode updated but bitmap not → the block could be double-allocated later, corrupting another file.
Key insight: without journaling, these partial-write scenarios are exactly what fsck has to detect; with journaling, the same scenario is analyzed against whether TxE was reached.
Q8Illustrate the full disk-access timeline for opening and reading file /foo/bar.HIGH▼
1
open(): start at root inode (root = inode 2) → read root inode's block → read root's directory data to find "foo" → read foo's inode block → read foo's directory data to find "bar" → read bar's inode block → check permissions → allocate a file descriptor.
2
read(): consult bar's cached inode for the first data block's location → read that data block → update last-accessed time → update the open-file table's offset.
3
close(): deallocate the descriptor — no disk I/O, pure in-memory bookkeeping.
Exam note: the writing variant (create() then write()) instead costs 5 I/Os per appended block: read/write data bitmap, read/write inode, write data block — plus extra I/O for a brand-new directory entry if the file is being created.
Q9A process calls fork(), then both parent and child run a loop writing to a shared array. What's the min/max number of new pages created after the fork?MED▼
1
Right after fork(), parent and child share all pages via copy-on-write (COW) — no new pages are created yet.
2
A new page is only created when either process writes to a shared page — the write triggers a copy so the two processes stop sharing that specific page.
3
Minimum new pages = 0 (if the loop never actually writes, e.g. it exits immediately or only reads). Maximum = the number of pages the array spans (if every page gets written to by at least one side).
Key insight: this tests COW understanding specifically, not standard demand-paging mechanics — the answer is a range (min/max), not a single number.
Q10Domain D1 has the Copy right on Object X. D1 copies the right to D2. Later, D1's rights are revoked. Does D2 still have the right? Update the access matrix.MED▼
1
Check whether the right was copied as a plain right or an asterisked right* — an asterisked copy can be re-copied further; a plain copy is one-generation-only.
2
Update D2's row/column entry for object X to add the copied right (matrix cell [D2, X] gains the right).
3
D1 losing the right afterward does not retroactively remove D2's already-copied right (copy is a one-time grant, not a live link) — unless the scenario specifies a revocation scheme (see Topic 30) that explicitly propagates.
Exam note: Protection questions are always small (2–5 marks) and always this style — an access-matrix right in use, or a static-domain "how do you add rights" scenario. Never a deep-recall question on revocation schemes.
Q1132-bit logical address space, page size 4 KB, page-table entry size 4 B. A process uses the maximum available logical memory. Find the total page-table size.MED▼
1
Offset bits = log2(4096) = 12. Page-number bits = 32 − 12 = 20.
2
Number of page-table entries = 2²⁰ = 1,048,576.
3
Total page-table size = entries × entry size = 1,048,576 × 4 B = 4,194,304 B = 4 MB.
Key insight: this is exactly why multilevel paging exists — a single-level table this large can't fit contiguously in one frame, motivating the split into multiple smaller tables (Q5).
∑ Mathematics ▼
Relocation / Base-Limit Protection
Physical = Logical + Relocation base ≤ address < base + limit → allowed, else trap
Address Translation (Paging)
page# = LA ÷ page_size (integer division) offset = LA mod page_size PA = (frame# × page_size) + offset
TLB Effective Access Time
EAT = hit×(TLB + mem) + miss×(TLB + mem + mem)
hit + miss = 1. Solve for any one variable (hit ratio, TLB time, mem time) given EAT and the rest.
EAT with Page Faults
EAT = (1 − p) × mem_access + p × page_fault_service_time
p = page-fault probability. page_fault_service_time is ~10⁵–10⁶× mem_access (disk-dominated).
Internal Fragmentation (Paging)
frag = page_size − (process_size mod page_size) [if remainder ≠ 0]
Worst case ≈ frame_size − 1. Average ≈ ½ a frame per process.
Multilevel Paging Derivation
n (offset bits) = log2(page size) P (page-number bits) = total address bits − n k (bits per level) = log2(frame size / entry size) levels needed = ceil(P / k)
Split P into k-bit chunks, innermost first; outermost level takes the leftover (≤ k bits).
Indirect-Block Indirection Math
Pointers per block = block size / pointer size Direct: N_direct blocks Single indirect: (ptrs/block)¹ blocks Double indirect: (ptrs/block)² blocks Triple indirect: (ptrs/block)³ blocks
Disk accesses to read a block (inode cached): direct=1, single=2, double=3, triple=4. Add 1 at every level if inode not cached.
Inode Address Calculation
Byte: offset = inode# × inode_size ; address = inode_table_start + offset Sector: block# = (inode# × inode_size) / block_size sector = (block# × block_size + inode_table_start) / sector_size
Fault Ratio / Hit Ratio (Page Replacement)
fault ratio = (faults / total references) × 100% hit ratio = 100% − fault ratio
ExPage size = 2,048 B, process size = 72,766 B. Find internal fragmentation.HIGH▼
1
72,766 ÷ 2,048 = 35 full pages, remainder 1,086 B (a 36th partial page).
2
Internal fragmentation = 2,048 − 1,086 = 962 bytes.
Pattern: fragmentation is only nonzero when the process size doesn't divide evenly into the page size — always check the remainder first.

C — fork() + demand paging scenario (reasoning, not tracing)
int arr[N];  // spans several pages

int main() {
    pid_t pid = fork();
    // both parent and child now share arr's pages via copy-on-write
    for (int i = 0; i < N; i++) {
        arr[i] = i;   // first WRITE to each page triggers a COW copy
    }
    ...
}
What to notice: no new pages exist immediately after fork() — sharing is free until a write happens. Each page gets copied at most once, on its first write from either parent or child. Min new pages = 0 (loop never runs), max = number of pages arr spans (every page written by at least one side).

🧠 Mnemonics & Memory Aids ▼
CIA + A
Security goals: Confidentiality, Integrity, Availability, + Authenticity.
PAON
4 official security levels: Physical, Application, OS, Network. (Humans are a cross-cutting risk, not a formal 5th level — don't add "Human" if asked to "name the 4 levels".)
What vs How
Violation categories = WHAT was violated (confidentiality/integrity/availability/theft-of-service/DoS). Violation methods = HOW it was done (masquerading/replay/MITM/session-hijacking/privilege-escalation).
1-2-3-4
Disk accesses by indirection level (inode cached): direct=1, single=2, double=3, triple=4 — one more access per level of indirection.
Two Different Skills
"Max file size" (sum across pointer levels) ≠ "inode disk address" (offset = inode# × inode_size). Both use inode structure but answer completely different questions — don't mix them up under time pressure.
Backward-Forward
LRU looks backward (what's been used least recently — knowable). Optimal looks forward (what won't be used for longest — unknowable, benchmark only).
ACL = Object, Capability = Domain
"Who can access this object?" → Access List, stored per object. "What can this process access?" → Capability List, stored per domain.
