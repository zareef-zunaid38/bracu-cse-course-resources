1 · Big Picture

Two programs, one binary image

simplefs_buildercreates empty FS
→
disk.img256 KiB
←
simplefs_adderadds test1.txt

Builder

Formats the image: zeroes it, writes metadata, allocates the root inode and root data block, then creates . and ...

Adder

Opens an existing image, validates it, finds free resources, copies a source file into data blocks, creates its inode, and gives it a name in the root directory.

Narration: The builder creates the world. The adder changes that world. If the builder layout is wrong, the adder cannot reliably operate.
2 · Starter Package

What each provided file is for

simplefs.h

Fixed constants and three structures: superblock_t, inode_t, dirent_t. Do not redesign them.

simplefs_builder.c

Contains 6 TODOs. Most file I/O scaffolding is already written.

simplefs_adder.c

Contains 11 TODOs. This is where allocation, lookup, copying, inode creation, and directory update happen.

README + test files

README gives compile/run commands. test1.txt, test2.txt, test3.txt are basic inputs.

Important: the official specification is the source of truth. Implement only the clearly marked TODO regions.

4 · Metadata

Three structures tell the whole story

Superblock

Describes the file system: magic number, block size, total blocks, locations of metadata regions, root inode.

Inode

Describes one file/directory: type, links, actual byte size, and up to 3 absolute data-block numbers.

Directory Entry

Gives an object a name by mapping name → inode_no. The file name is not stored in the inode.

6 · Bitmaps

A single bit answers “free or used?”

Inode bitmap after formatting

10000000

Bit 0 is 1 because inode 1 is the root.

Data bitmap after formatting

10000000

Bit 0 is 1 because it represents absolute Block 4, the root directory.

inode bitmap index = inode number - 1
absolute data block = DATA_REGION_BLOCK + data bitmap index
Narration: The two bitmaps use similar-looking bits but different numbering. This is one of the most common sources of bugs.

Why size = 128?

. is 64 bytes + .. is 64 bytes = 128 bytes.

11 · Adder TODOs 1–4

Search before you allocate

TODO 1 · free inode

Scan bitmap indexes 1 through 31. First zero bit wins. Return inode number, so convert index → inode number.

TODO 2 · free data block

Scan data bitmap from index 0. First zero bit wins. Return absolute block number, not bitmap index.

TODO 3 · duplicate name

Seek to Block 4, read directory entries, ignore unused entries, compare existing names with the requested file name.

TODO 4 · free dirent

Search root entries 2..63 because entries 0 and 1 are reserved for . and ... inode_no == 0 means unused.

12 · Adder TODOs 5–7

How many blocks? Which blocks? Then copy.

TODO 5 · required blocks

required_blocks = ceiling(file_size / 4096)
100 B → 1     4096 B → 1     4097 B → 2
5000 B → 2    8193 B → 3     0 B → 0

TODO 6 · allocate in memory

Repeat first-fit search for the required count. Save each absolute block in allocated_blocks[] and mark its corresponding bitmap bit in the in-memory bitmap.

TODO 7 · copy bytes

For each allocated block: zero a 4096-byte buffer, read up to 4096 bytes from source, seek to the absolute block, write the full buffer.

Zeroing the buffer matters: the final block may be only partly occupied by real file data.
13 · Adder TODOs 8–11

Make the copied bytes discoverable

TODO 8 · new inode

Regular-file type, link count 1, actual byte size, and allocated absolute block numbers in direct[].

TODO 9 · inode bitmap

Convert the chosen inode number to its bitmap index and mark it allocated.

TODO 10 · directory entry

Store inode number, file type, and source name. Respect the 58-character filename limit and null termination.

TODO 11 · root size

One new directory entry was added, so root inode size increases by sizeof(dirent_t) = 64 bytes.

15 · C Skills You Need

fseek is your disk head

Position

fseek(image, block_number * BLOCK_SIZE, SEEK_SET);

Moves to the beginning of a block.

Transfer

fread(&object, sizeof(object), 1, image);
fwrite(&object, sizeof(object), 1, image);

Moves bytes between C memory and the image.

17 · Binary Inspection

Running is not the same as being correct

Root directory

xxd -s 16384 -l 128 disk.img

After formatting, ASCII should expose . and ...

First user data block

xxd -s 20480 -l 100 disk.img

If the first small file gets Block 5, its content should appear here.

For an independent test, recreate a fresh image first so previous allocations do not change the expected values.
18 · Debugging

Five mistakes to catch early

1 · Wrong numbering

Storing a bitmap index in direct[] instead of the absolute block number.

2 · Missing metadata update

Copying data but forgetting bitmap, inode, directory entry, or root-size update.

3 · Wrong size

For a 5000-byte file, inode size is 5000 — not 8192.

4 · Bad filename handling

Ignoring the 58-character limit or failing to null-terminate the 59-byte name field.

5 · Testing on dirty state

Expecting first-file allocations after earlier files already changed the image.

19 · Quick Check

A first file needs one data block. Which values are expected?

Correct: inode 2 and absolute Block 5. Inode 1 and Block 4 already belong to the root.
20 · Quick Check

A file is 8193 bytes. How many direct pointers are used?

Correct: 3. Two blocks hold 8192 bytes; one additional byte requires the third block.
