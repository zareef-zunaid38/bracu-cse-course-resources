# Understanding the xv6 Scheduler

A beginner's guide to the xv6 round-robin scheduler, process table, spinlocks, CPU structures, context switching with swtch(), and timer interrupt preemption.

### 1. What Kind of Scheduler Does xv6 Use?
xv6 uses a **round-robin scheduler**:
- Every `RUNNABLE` (ready) process gets an opportunity to execute.
- The OS scans through the process table in order.
- The first `RUNNABLE` process found is selected.
- After a short time slice (time quantum), the process is preempted.
- The scheduler continues scanning to run the next `RUNNABLE` process.

### 2. The Process Table (`proc[]`)
xv6 maintains all process information in a global array in `kernel/proc.c`:
```c
struct proc proc[NPROC];
```
Each entry stores metadata and runtime state:
- Process ID (`pid`)
- Page table pointer
- Context registers
- Open file descriptors
- Process name
- Process state (`state`): `UNUSED`, `USED`, `SLEEPING`, `RUNNABLE`, `RUNNING`, `ZOMBIE`

The scheduler only selects processes whose state is `RUNNABLE`.

### 3. Locks in xv6
xv6 protects shared kernel data across multiprocessor CPUs using spinlocks. Each process structure contains its own lock:
```c
struct spinlock lock;
```
**Why locks are necessary:**
- The scheduler and other kernel functions (`sleep()`, `wakeup()`, `exit()`) modify process fields concurrently across CPU cores.
- xv6 requires acquiring a process's lock before reading or modifying critical fields, and releasing it when finished.
- Prevents race conditions with interrupts or actions on other CPUs.

### 4. Where the Scheduler Runs
After initializing hardware and kernel subsystems, xv6 starts the scheduler:
```c
void main(){
    // initialize hardware, start first user process...
    scheduler();   // never returns
}
```
Each CPU core permanently sits inside `scheduler()`.

### 5. Understanding `mycpu()`
Each CPU core has a dedicated `struct cpu` object:
```c
struct cpu *c = mycpu();
```
Inside this structure:
- `c->proc`: Points to the process currently running on that CPU (or `0` / `NULL` if the CPU is in the scheduler).
- Tracks active execution, register save locations, and resume addresses.

### 6. The Scheduler Loop Explained
Simplified core scheduler implementation from `kernel/proc.c`:
```c
for(;;){
  for(p = proc; p < &proc[NPROC]; p++){
    acquire(&p->lock);
    if(p->state == RUNNABLE){
      p->state = RUNNING;
      c->proc = p;
      swtch(&c->context, &p->context);
      c->proc = 0;   // when process stops running
    }
    release(&p->lock);
  }
}
```

**Step-by-Step Walkthrough:**
- **Step 1 — Forever Loop**: Outer `for(;;)` runs indefinitely to keep finding work for the CPU core.
- **Step 2 — Scan All Processes**: Inner loop iterates sequentially through `proc[NPROC]` searching for `RUNNABLE` processes.
- **Step 3 — Lock the Process**: Calls `acquire(&p->lock)` before examining or modifying process state to prevent kernel races.
- **Step 4 — Run the Process**: Sets `p->state = RUNNING;`, assigns `c->proc = p;`, and executes `swtch(&c->context, &p->context);`. `swtch` saves scheduler registers and restores process registers. Execution switches directly to the process.
- **Step 5 — Returning to Scheduler**: When the process yields, sleeps, or exits, execution returns right after `swtch()`. `c->proc` is reset to `0` (CPU is idle in scheduler), and `p->lock` is released.

### 7. How a Time Quantum Causes a Context Switch
Preemption cycle:
1. Hardware timer triggers an interrupt every time slice.
2. xv6 enters the trap handler.
3. Trap handler recognizes the timer interrupt and calls `yield()`.
4. `yield()` acquires process lock, resets state to `RUNNABLE`, and calls `sched()`.
5. `sched()` invokes `swtch(&p->context, &c->context)` to save process registers and return control back to the scheduler loop.
6. The scheduler then selects the next available `RUNNABLE` process.\n
