# CSE321 Module 06: Memory Management — sidecar (read this, not the .pptx)

Lecture slides covering main memory management, address binding, logical vs physical addresses, contiguous memory allocation (First-Fit, Best-Fit, Worst-Fit), fragmentation, paging, TLB translation, page tables, and virtual memory page replacement (FIFO, Optimal, LRU).
Pptx last modified: 28-08-2025.

## Content

### Slides 1–6: Background & Address Binding
- Program must be brought from disk into memory and placed within a process context to be run.
- Main memory and CPU registers are the only storage CPU can access directly.
- **Memory Protection:** Hardware base and limit registers define logical address space range; CPU hardware compares every generated address with registers to prevent process from accessing other processes' memory.
- **Address Binding:** Mapping program instructions and data to physical memory addresses:
  - *Compile time:* If memory location known a priori, absolute code generated. Must recompile if starting location changes.
  - *Load time:* If memory location not known at compile time, relocatable code generated.
  - *Execution time:* If process can be moved during execution between memory segments, binding delayed until runtime (requires hardware support like MMU).

### Slides 7–10: Logical vs Physical Address Space
- **Logical (Virtual) Address:** Address generated by the CPU.
- **Physical Address:** Address loaded into the memory address register (MAR) of memory.
- **Memory-Management Unit (MMU):** Hardware device that maps virtual to physical addresses at runtime.
  - In simple scheme, base register is called **relocation register**:
    $$\text{Physical Address} = \text{Logical Address} + \text{Relocation Register}$$

### Slides 11–15: Dynamic Loading, Linking & Contiguous Allocation
- **Dynamic Loading:** Routine is not loaded until it is called. Unused routines are never loaded $ightarrow$ better memory-space utilization.
- **Dynamic Linking:** Linking postponed until execution time. Small stub used to locate library routine; stub replaces itself with address of routine and executes it.
- **Contiguous Allocation:**
  - Memory divided into fixed or variable partitions. Each process contained in a single contiguous section of memory.
  - **Dynamic Storage Allocation Strategies:**
    - **First-Fit:** Allocate the *first* hole that is big enough. Fast search.
    - **Best-Fit:** Allocate the *smallest* hole that is big enough. Produces smallest leftover hole. Must search entire list unless sorted by size.
    - **Worst-Fit:** Allocate the *largest* hole. Produces largest leftover hole (more useful). Must search entire list.

### Slides 16–19: Fragmentation
- **External Fragmentation:** Total memory space exists to satisfy request, but it is not contiguous (scattered in many small holes).
  - *50-percent rule:* Given $N$ allocated blocks, approximately $0.5 N$ blocks lost to fragmentation.
  - Reduced by **Compaction** (shuffling memory contents to place all free memory together; only possible with dynamic runtime relocation).
- **Internal Fragmentation:** Allocated memory may be slightly larger than requested memory; unused memory internal to a partition/page.

### Slides 20–28: Paging & Address Translation
- Non-contiguous memory allocation scheme that eliminates external fragmentation.
- **Concepts:**
  - Physical memory divided into fixed-size blocks called **Frames** (power of 2, typically 512 bytes to 1 GB).
  - Logical memory divided into same-sized blocks called **Pages**.
  - OS maintains a **Page Table** for each process to translate logical addresses to physical addresses.
- **Address Translation Architecture:**
  - Logical address generated by CPU divided into two parts:
    - **Page Number ($p$):** Used as an index into a page table containing base address of each page in physical memory.
    - **Page Offset ($d$):** Combined with base address to define physical address.
    - If logical address space is $2^m$ and page size is $2^n$: $p = m - n$ bits, $d = n$ bits.
    - $\text{Physical Address} = (f \times \text{Page Size}) + d$, where $f$ is frame number.

### Slides 29–34: Translation Lookaside Buffer (TLB) & Effective Access Time
- Accessing memory requires 2 memory accesses per instruction: one for page table entry, one for actual byte.
- **TLB (Translation Lookaside Buffer):** Fast associative hardware cache storing recently used page-table mappings.
- **Effective Access Time (EAT):**
  - Let $\text{TLB Hit Ratio} = \alpha$, $\text{TLB Search Time} = \epsilon$, $\text{Memory Access Time} = m$:
    $$\text{EAT} = (\epsilon + m)\alpha + (\epsilon + 2m)(1 - \alpha) = \epsilon + m(2 - \alpha)$$

### Slides 35–40: Virtual Memory & Page Replacement Algorithms
- **Virtual Memory:** Separation of user logical memory from physical memory. Allows execution of processes not completely in memory.
- **Demand Paging:** Bring page into memory only when needed during execution. If page not present, MMU triggers a **Page Fault trap** $ightarrow$ OS brings page from backing store to free frame and updates page table.
- **Page Replacement Algorithms (evaluated by counting page faults on reference strings):**
  1. **FIFO (First-In, First-Out):** Replaces oldest page brought into memory. Suffers from **Belady's Anomaly** (more frames may cause more page faults).
  2. **Optimal Page Replacement (OPT):** Replaces page that will not be used for the longest period of time. Minimum possible page faults; used as benchmark (unimplementable in practice because future references unknown).
  3. **LRU (Least Recently Used):** Replaces page that has not been used for longest period of time (associates time of last use). Does not suffer from Belady's anomaly. Implemented using counters or stack.
