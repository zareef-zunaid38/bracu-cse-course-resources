📖 Theory ▼
DFA — Formal Definition HIGH

A Deterministic Finite Automaton is a 5-tuple M = (Q, Σ, δ, q₀, F) where:

  • Q — finite, non-empty set of states
  • Σ — finite input alphabet
  • δ: Q × Σ → Q — transition function (must be total)
  • q₀ ∈ Q — start state
  • F ⊆ Q — set of accept states (may be empty)

The DFA accepts string w if reading w from q₀ ends in a state that belongs to F.

Critical: δ must be defined for every (state, symbol) pair. A DFA with undefined transitions is not a valid DFA. If a string leads to guaranteed rejection, route it to a dead state — never leave a transition undefined.
DFA Construction Strategy HIGH

The design question is always: what does the machine need to remember at each point in the input? Each distinct "memory configuration" becomes one state.

  • Counting mod n → n states (one per remainder value)
  • Tracking last k characters → up to |Σ|ᵏ states
  • Substring matching → states track "longest prefix of target matched so far"

After drawing: trace an accepting string and a rejecting string manually. If either gives the wrong result, your state design is wrong.

Process: (1) Identify what to remember → (2) Name states → (3) Fill transitions for every state × every symbol → (4) Mark start and accept states → (5) Verify with test strings.
Dead (Trap) State MED

A dead state is a non-accepting state where every transition loops back to itself. Once entered, the machine can never accept.

Needed when: the input seen so far makes acceptance permanently impossible, regardless of future input.

Common error: Not drawing the dead state explicitly. If your DFA has states that lack transitions for some symbol, it is invalid. Add the dead state and route those transitions there.
Cross Product Construction HIGH

Given M₁ = (Q₁, Σ, δ₁, q₁, F₁) and M₂ = (Q₂, Σ, δ₂, q₂, F₂), the cross product DFA is:

  • States: Q₁ × Q₂ = all pairs (r, s) where r ∈ Q₁ and s ∈ Q₂
  • Start state: (q₁, q₂)
  • Transition: δ((r, s), a) = (δ₁(r, a), δ₂(s, a)) — advance both simultaneously
  • Accept (intersection): F = {(r, s) | r ∈ F₁ and s ∈ F₂}
  • Accept (union): F = {(r, s) | r ∈ F₁ or s ∈ F₂}
Key insight: The cross product runs both DFAs simultaneously. At every step, both components advance on the same input symbol. The combined state tracks where each machine is independently.
Regular Operations Recap LOW

Note: Regular expressions are excluded from this quiz (TNF announcement). Know this for context only.

Union (A ∪ B), Concatenation (A ∘ B), and Kleene Star (A*) are the three regular operations. DFAs are closed under all of them. The cross product directly constructs the DFA for union and intersection.

❓ Short Questions ▼

Tap a question to reveal the answer. Recall first.

What are the 5 components of a DFA? State each component's type. HIGH
M = (Q, Σ, δ, q₀, F).
Q: finite set of states.
Σ: finite input alphabet.
δ: Q × Σ → Q: total transition function.
q₀ ∈ Q: start state.
F ⊆ Q: set of accept states.
Why must δ be a total function? What happens if it is not? HIGH
A DFA must process any input without getting stuck. If δ(q, a) is undefined for some state q and symbol a, the machine has no valid move when it reads a in state q — it is not a well-defined DFA. The fix is to add a dead (trap) state and route all "reject-forever" transitions there. Dead state has self-loops on every symbol and is not an accept state.
What is a dead (trap) state? Give an example of when one is needed. MED
A non-accepting state where every transition loops back to itself. Once entered, no future input can lead to acceptance. Example: DFA for "strings that start with 'a'" — if the first character is 'b', the machine can never accept regardless of what follows. Move to a dead state and loop there forever.
DFA A has 3 states, DFA B has 4 states. How many states does their cross product have? HIGH
3 × 4 = 12 states. One combined state (rᵢ, sⱼ) for every pair where rᵢ ∈ Q_A and sⱼ ∈ Q_B. Note: not all 12 may be reachable from the start state, but the construction creates all of them. In practice you only need reachable states, but creating all of them first is safer in an exam.
How do accept states differ between intersection and union in cross product construction? HIGH
Intersection: (r, s) is an accept state if and only if r ∈ F₁ AND s ∈ F₂. Both components must be in their own accept states simultaneously.

Union: (r, s) is an accept state if r ∈ F₁ OR s ∈ F₂. It is enough for at least one component to be accepting.
🧮 Analytical Questions ▼
Q1 LARGE — Construct a DFA over {a, b} that accepts all strings containing "aba" as a substring. HIGH ▼
1
What to remember: the longest suffix of input seen so far that is a prefix of "aba". This gives 4 memory configurations: none matched (q0), matched "a" (q1), matched "ab" (q2), matched "aba" (q3 — accept).
2
States: Q = {q0, q1, q2, q3}. Start: q0. Accept: {q3}.
3
Transitions:
Stateon aon bNote
q0 (start)q1q0"a" starts pattern; "b" resets
q1q1q2another "a" still holds "a" prefix; "b" advances to "ab"
q2q3q0"a" completes "aba"; "b" → "abb", no prefix matches → reset
q3 (accept)q3q3pattern found; stay accepted regardless of future input
4
Verify: Trace "baba": q0→q0→q1→q2→q3 ✓ (accept). Trace "ab": q0→q1→q2 (reject) ✓. Trace "aaba": q0→q1→q1→q2→q3 ✓ (accept).
Common error: The transition q1 on 'a' goes back to q1, NOT to q0. "aa" still ends in "a", so the first character of "aba" is still matched. Many students reset to q0 here — wrong.
Exam note: Always check q2 on 'b' carefully. "abb" has no prefix of "aba" as a suffix — it resets to q0, not q1. Draw the reset arrows; they are the hardest to get right.
Q2 LARGE — Construct a DFA over {0, 1} that accepts strings where the number of 1s is divisible by 3. HIGH ▼
1
What to remember: (count of 1s seen so far) mod 3. The remainder can be 0, 1, or 2 — giving 3 states.
2
States: Q = {r0, r1, r2}. Start: r0 (0 mod 3). Accept: {r0} only — 0 is divisible by 3, so the empty string is accepted.
3
Transitions:
Stateon 0on 1Note
r0 (start/accept)r0r1#1s ≡ 0 mod 3
r1r1r2#1s ≡ 1 mod 3
r2r2r0#1s ≡ 2 mod 3
4
Verify: "0" → r0→r0 (accept) ✓. "1" → r0→r1 (reject) ✓. "111" → r0→r1→r2→r0 (accept) ✓. "101" → r0→r1→r1→r2 (reject) ✓.
Key insight: 0s don't change the count — they are self-loops on every state. 1s cycle through remainders: 0→1→2→0→... This pattern applies to any "count mod n" problem with n states cycling on the counted symbol.
Exam note: r0 is BOTH start AND accept (empty string has 0 ones, 0 is divisible by 3). Students sometimes forget r0 is an accept state. Mark it with a double circle.
Q3 SMALL — Construct a DFA over {0, 1} that accepts strings ending in '0'. MED ▼
1
What to remember: only the last character seen. Two cases: last char was 0, or it wasn't (empty string or last was 1). Both non-accepting cases behave identically → 2 states total.
2
States: Q = {qe, q0}. Start: qe (not accept — empty string does not end in 0). Accept: {q0}.
3
Transitions:
Stateon 0on 1
qe (start)q0qe
q0 (accept)q0qe
4
Verify: "0" → qe→q0 ✓. "10" → qe→qe→q0 ✓. "01" → qe→q0→qe (reject) ✓. "" → qe (reject) ✓.
Key insight: Both "empty string" and "last char was 1" behave identically (transitions and accept status are the same), so they collapse into one state. If two situations are indistinguishable going forward, they are the same state.
Q4 CROSS PRODUCT — Intersection of Q2 and Q3: strings where #1s ≡ 0 (mod 3) AND the string ends in '0'. HIGH ▼
1
Input DFAs: DFA A (Q2 above) has states {r0, r1, r2}; DFA B (Q3 above) has states {qe, q0}.
2
Cross product states: 3 × 2 = 6. Label: (rᵢ, qⱼ). Start: (r0, qe). For intersection, accept only where r ∈ {r0} AND q ∈ {q0} → accept = {(r0, q0)} only.
3
Transition table — δ((r, q), sym) = (δ_A(r, sym), δ_B(q, sym)):
Stateon 0on 1
(r0, qe) start(r0, q0)(r1, qe)
(r0, q0) ACCEPT(r0, q0)(r1, qe)
(r1, qe)(r1, q0)(r2, qe)
(r1, q0)(r1, q0)(r2, qe)
(r2, qe)(r2, q0)(r0, qe)
(r2, q0)(r2, q0)(r0, qe)
4
Verify: "0" → (r0,qe)→(r0,q0) ACCEPT ✓ [0 ones, ends in 0]. "10" → (r0,qe)→(r1,qe)→(r1,q0) REJECT ✓ [1 one, ends in 0 but 1≢0 mod 3]. "1110" → (r0,qe)→(r1,qe)→(r2,qe)→(r0,qe)→(r0,q0) ACCEPT ✓ [3 ones, ends in 0].
Key insight: Each row is computed mechanically — you don't need to reason about the combined language. Just apply δ_A and δ_B independently for each symbol, then pair the results. Fill the table row by row without skipping.
Exam note: For union instead of intersection, the accept states would be: all (r, q) where r = r0 OR q = q0. That gives: {(r0,qe), (r0,q0), (r1,q0), (r2,q0)}. Confirm which operation is asked before marking accept states.
∑ Mathematics ▼
DFA Formal Tuple
M = (Q, Σ, δ, q₀, F)
Q = states · Σ = alphabet · δ: Q×Σ→Q (total) · q₀ = start · F = accept states
Extended Transition Function δ*
δ*(q, ε) = q δ*(q, wa) = δ(δ*(q, w), a)
δ* reads a full string. δ reads one symbol. L(M) = { w ∈ Σ* | δ*(q₀, w) ∈ F }
Cross Product State Count
|Q₁ × Q₂| = |Q₁| · |Q₂|
Cross product transition: δ((r,s), a) = (δ₁(r,a), δ₂(s,a)) Intersection accept: r ∈ F₁ AND s ∈ F₂ Union accept: r ∈ F₁ OR s ∈ F₂

🧠 Mnemonics & Memory Aids ▼
Q Σ δ q₀ F — "Quite Surely, Delta Queries Forward"
The 5-tuple in order: states, alphabet, transition, start, accept. Write this at the top of every DFA answer to anchor the definition before drawing anything.
DEAD: "Dead Ends Accept Daily — never"
Dead state = all transitions loop back to itself, never an accept state. Once the machine enters, it stays. Needed whenever rejection is permanent.
Cross product: AND = Both · OR = Either
Intersection → both components in accept state. Union → either component in accept state. Say it aloud before marking accept states in the cross product table.
Memory = States
The number of distinct things a DFA needs to remember = the minimum number of states. Can't remember more than you have states. Use this to sanity-check your design: "does each state represent exactly one memory configuration?"
The best mnemonics are the ones you invent mid-exam. Write them in the margin and circle them.
